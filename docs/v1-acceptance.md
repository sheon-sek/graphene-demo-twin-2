# v1 issues as v2 acceptance tests

The PRD (#11) turns every v1 issue into an acceptance test on the v2 world, and closes the v1
issues as superseded when v2 merges to `main`. Each row below names the tests that pass on
v2. `tests/test_docs.py` checks that every test named here exists and that each issue
from #2 to #10 has a row.

| v1 issue | What was wrong in v1 | v2 acceptance tests | Supersession note |
|---|---|---|---|
| #2 | `NETWORK_DEVICE_FAILURE` left the same device healthy on its `Network Topology/*` export instance. | `tests/test_network.py::test_the_port_view_reads_the_same_device_as_the_topology_view` | Both export views of a switch read one device's AssetState, so they cannot disagree. |
| #3 | Healthy leak cables reported `Status = 1`, because a generic Int fallback treated cable Status as run status. | `tests/test_water.py::test_healthy_leak_cables_report_no_leak`, `tests/test_water.py::test_a_leak_in_dh03_trips_its_level_1_cable_once_water_reaches_it` | Cable Status is an alarm bit that the water network drives. No production point has a fallback (`tests/test_audit.py::test_the_audit_is_green`). |
| #4 | Hall-B humidity evidence was unreachable: there was no Hall-B thermal zone. | `tests/test_thermal.py::test_each_data_hall_and_each_support_room_with_air_units_is_its_own_zone`, `tests/test_thermal.py::test_losing_cooling_in_dh05_raises_only_dh05`, `tests/test_thermal.py::test_a_warmer_hall_holds_the_same_moisture_at_a_lower_relative_humidity` | "Hall-A/Hall-B" is gone. Each of DH01–DH08 is its own Thermal Zone, with temperature and moisture, observed by its own sensors. |
| #5 | Zero chiller production still read as nominal CHW supply: a plant fallback masked total plant failure. | `tests/test_cooling_faults.py::test_all_chillers_stopped_warms_the_chilled_water_on_every_observer` | The chilled water is integrated physics that every Plant View observes. |
| #6 | After fault inject/clear cycles the world stayed dead: Reset did not heal it, but a restart did. | `tests/test_sim.py::test_reset_is_indistinguishable_from_a_fresh_process`, `tests/test_twin.py::test_reset_publishes_a_fresh_world_in_a_new_epoch`, `tests/test_thermal.py::test_clear_lets_the_hall_recover_through_its_own_inertia` | Reset rebuilds from the initial state (ADR-0003), and Clear recovers through the world's own dynamics. |
| #7 | Fault injection needed to be stronger: aimed at a chosen asset, previewed, and cleanly undone. | `tests/test_faults.py::test_a_fault_acts_on_the_chosen_asset_and_never_on_another_of_its_type`, `tests/test_twin.py::test_faults_are_injected_on_exactly_the_chosen_asset`, `tests/test_faults.py::test_a_preview_reports_alarm_bits_a_transient_fault_raises_then_clears`, `tests/test_golden_demo.py::test_the_golden_demo_tells_its_story_through_the_physics` | The fault framework has 84 catalogued faults in five categories (see `docs/fault-catalog.md`), with Fault Preview in a What-if Fork and per-fault Clear. The console fault workflow is covered by `apps/web/src/__tests__/faults.test.tsx`. |
| #8 | The tower energy timeline needed bounding to the Cooling Tower and PAHU drivers, excluding chiller ramps. | `tests/test_sim.py::test_energy_integrals_accumulate_step_by_step`, `tests/test_sim.py::test_reaching_any_instant_never_reintegrates_history` | Superseded by stateful stepping (ADR-0003). Each energy register integrates its own asset's power step by step, so no timeline is re-derived and nothing unbounded remains. |
| #9 | Hall-B should have stayed compatibility state, since an unmet-cooling penalty contradicted the migration boundary. | `tests/test_thermal.py::test_delivered_fraction_is_the_share_of_demand_met_through_loss_and_recovery`, `tests/test_audit.py::test_the_audit_is_green` | Superseded. v2 has no compatibility state for any hall: every hall is physics, unmet cooling is its Delivered Fraction, and the zero-fallback audit forbids production fallbacks. |
| #10 | The `opc` subcommand was removed in the physics PR, and `serve` binds 4840 by default. | `tests/test_cli.py::test_serve_is_the_only_command`, `tests/test_cli.py::test_serve_starts_api_console_and_opc_ua_together_and_stops_on_sigint`, `tests/test_surfaces.py::test_opc_ua_browses_the_export_reads_sim_time_and_rejects_writes` | One process serves REST/SSE, the console and OPC UA on 4840 (`docs/cli.md`). |

Some of these tests are marked `slow` and run in CI (`pytest -m 'slow or not slow'`), not in the default local run.
